# CropOptimize — правила платформы

**Этот файл — точка входа новой сессии.**  
Прочитай его целиком до любых правок. Он важнее `docs/design.md` для решений «можно ли менять оболочку / визуал / навигацию».  
`docs/design.md` — спецификация экрана «Культуры». Этот файл — конституция всей платформы.

Продукт: **CropOptimize**  
Пользователи: агроном и администратор организации  
Язык UI: **русский**  
Состояние: MVP, каркас зафиксирован, экран «Культуры» — эталон

---

## 0. Главное правило

**Основной дизайн заморожен. Фичи только расширяют текущую платформу. Интерфейс не перестраивается.**

Запрещено:

- менять визуальный язык (цвета, шрифт, радиусы, тени, плотность)
- пересобирать layout (sidebar + top bar + content)
- вводить другой UI-kit / CSS-фреймворк / тему
- «улучшать» карточки, хедер, табы или навигацию без явной задачи
- дублировать примитивы (`Button`, `Modal`, `Drawer`, `Badge`, поля форм)
- класть новую информацию на карточку списка, если она не входит в 5 ключевых параметров

Разрешено:

- заполнять существующие placeholder-экраны в том же каркасе
- добавлять пункты навигации **в конец** списка, не переставляя текущие
- добавлять Drawer / Modal / toast по уже принятым паттернам
- расширять модели данных и репозитории
- подключать API вместо mock, не меняя UI-контракт

Если хочется сменить цвет, сетку, сайдбар, типографику или «сделать современнее» — **не делать**. Это нарушение контракта.

## 1. Стек (не менять без причины)

| Слой | Выбор |
|---|---|
| Сборка | Vite 7, alias `@/` → `src/` |
| UI | React 19 + TypeScript (strict) |
| Роутинг | `react-router-dom` v7, `createBrowserRouter` |
| Данные | TanStack Query v5 |
| Иконки | `lucide-react` |
| Стили | CSS Modules + CSS-переменные из `src/app/styles/tokens.css` |
| Состояние экрана | URL search params + локальный UI-state |

Не добавлять: Tailwind, MUI, Ant, styled-components, Redux, новый шрифт, новую палитру.  
Яндекс.Карты — исключение только для карты полей, не замена UI-kit. Не подключать Leaflet / Mapbox / Google.

Запуск:

```bash
npm install
npm run dev      # http://localhost:5173 → /login, затем Dashboard
npm run build
```

### 2.1. Sidebar — не переставлять

Источник: `src/layouts/navigation.ts`

Порядок **зафиксирован**:

1. Dashboard → `/dashboard` (`LayoutDashboard`)
2. Планы расчёта → `/plans` (`ClipboardList`)
3. Поля → `/fields` (`Map`)
4. Культуры → `/crops` (`Sprout`)
5. Сотрудники → `/employees` (`Users`)

Неактивный: `#5C6B5C`. Hover неактивного: фон `--color-primary-light`.

Новый раздел: добавить пункт **в конец** `PRIMARY_NAV` (перед Settings). Не менять иконки и подписи существующих пунктов. Не делать вложенное меню.

`/` — публичный лендинг (тёмная маркетинговая поверхность, не оболочка кабинета). Код: `src/features/landing/`. Не переносить токены лендинга в кабинет и не перекрашивать кабинет под лендинг.

### 2.2. Top Bar — состав зафиксирован

Слева направо:

1. Кнопка меню (только <1024px)
2. Поиск
3. Селектор сезона (`2026` / `2025` / `2024`)
4. Уведомления (колокол)

Placeholder меняется (`Поиск культур...` / `Поиск полей...` / `Поиск сотрудников...`), стиль инпута — нет.

## 4. Визуальный язык компонентов

Эталон — экран «Культуры» и `src/shared/ui/`.

### 4.1. Кнопки (`Button`)

| variant | Когда |
|---|---|
| `primary` | главное действие экрана / сабмит формы |
| `ghost` | «Отмена», второстепенное текстовое действие |
| `secondary` | альтернатива primary, контур |

Размеры: `md` (42px) по умолчанию, `sm` (34px) только во вспомогательных местах.  
Радиус 10px. Primary hover = `#1B5E20`.  
Текст действия создания: иконка `Plus` + глагол («Добавить культуру»), не выдумывать другой стиль CTA.

### 4.2. Карточки списка

- фон белый, бордер `1px solid --color-border`, радиус 16px, padding 20–24px
- тень `--shadow-card`, hover — `--shadow-card-hover` + `translateY(-1px)`
- заголовок карточки: 18px / 700
- кликабельна целиком, `cursor: pointer`
- «Подробнее» появляется на hover / focus, не отдельная конкурирующая кнопка
- клавиатура: `tabIndex={0}`, Enter / Space открывают детали

На карточке **максимум 5 ключевых параметров**. Всё остальное — в Drawer.

### 4.3. Badge статуса

Текст обязателен (не цвет alone):

| status | Текст | Фон / текст |
|---|---|---|
| `sowing_now` | Сеем сейчас | `#E8F5E9` / `#2E7D32` |
| `planned` | Планируем | `#FFF8E1` / `#F9A825` |
| `history` | История | `#F5F5F5` / `#90A4AE` |

Статус — главный визуальный маркер сущности. Не заменять его на точки, иконки без подписи или другой набор лейблов.

### 4.4. Табы / фильтры

Горизонтальные текстовые табы с нижней границей.  
Активный: зелёный текст + нижняя граница primary + лёгкий `--color-primary-light`.  
Неактивный: `--color-text-secondary`.  
Не заменять на pills / segmented control другого стиля, если уже есть табы на экране.

### 4.5. Типографика страницы

- `h1` экрана: 26px / 700 / `--color-text-primary` («Культуры организации» — эталон)
- вторичный текст: `--color-text-secondary`
- числа урожайности: `ru-RU`, один знак после запятой, единица `т/га` (`formatYield`)
- диапазон дат: `25.04 – 15.05` (`formatSowingWindow`)

### 4.6. Сетка списков

Как у культур (повторять на новых каталогах, если это карточки):

- ≥1280px — 3 колонки
- 1024–1279px — 2 колонки
- <1024px — 1 колонка
- gap `22px`

Длинные операционные списки (планы, поля) можно делать таблицей/списком, но в той же контентной колонке и с тем же header-паттерном.

### 4.7. Overlay-паттерны (не путать)

| Паттерн | Когда | Ширина |
|---|---|---|
| **Modal** | создание / короткое подтверждение | ≤520px, по центру |
| **Drawer** (справа) | детали сущности, история, связанные объекты | 420–480px (`min(460px, 100%)`) |
| **Toast** | короткий результат действия | низ-право, ~2.8с |
| **Отдельный route** | полноценный рабочий экран (список, мастер из нескольких шагов) | контент layout |

Не открывать детали карточки новой страницей, если уже принят Drawer.  
Не делать создание через Drawer, если уже принята Modal.  
Escape и клик по overlay закрывают. `body` overflow hidden на время открытия.

После успешного создания:

1. закрыть модалку
2. сущность появляется в списке
3. toast с коротким фактом («Культура добавлена»)

### 4.8. Состояния экрана

Каждый список обязан иметь все четыре:

1. **Loading** — skeleton в той же сетке, 3–6 штук, пульс
2. **Empty** (данных нет) — иконка + заголовок + пояснение + primary CTA
3. **Error** — иконка + «Не удалось загрузить …» + «Повторить»
4. **Filtered empty** — «Ничего не найдено», без CTA создания, если данные есть, но фильтр пуст

Не спиннер по центру вместо skeleton. Не пустой белый экран.

## 5. Accessibility (обязательно)

- интерактивные элементы получают `:focus-visible`
- контраст текста ≥ 4.5:1 (тёмно-зелёный текст на светлом фоне уже заложен)
- карточки доступны с клавиатуры
- badge несёт текст, не только цвет
- декоративные иконки: `aria-hidden="true"` + текстовая метка рядом
- диалоги: `role="dialog"`, `aria-modal`, заголовок через `aria-labelledby`
- тосты: `role="status"` + `aria-live="polite"`

## 6. Архитектура кода

Feature-based. Новая фича = новая папка, **не** размазывать по `pages/` и не раздувать `CropsScreen`.

```
src/
  app/                 # провайдеры, роутер, глобальные стили — трогать минимально
  layouts/             # ОБОЛОЧКА. Менять только чтобы добавить nav-пункт
  pages/               # тонкие route-обёртки, без бизнес-логики
  features/<name>/     # домен фичи
    api/               # repository + query keys + seed/mock
    model/             # types + labels
    hooks/             # useQuery / useMutation
    lib/               # чистые функции (фильтры, мапперы)
    components/        # UI фичи
  shared/ui/           # примитивы платформы
  shared/lib/          # cn, format*
```

Правила:

- страница = `pages/XPage.tsx`, который рендерит `features/x/components/XScreen`
- импорты через `@/`
- CSS Modules рядом с компонентом
- типы и русские лейблы — в `model/`, не размазывать строки по JSX без нужды
- query keys — объект `xKeys.all`, инвалидация после мутаций
- mock-репозиторий имитирует сеть (`delay`) и при необходимости пишет в `localStorage`
- ключ стора культур: `cropoptimize.crops.v1` — не ломать без миграции

Когда появится бэкенд: заменить тело `*Repository`, UI и хуки оставить. Не тащить `fetch` в компоненты.

Связи между доменами (культура ↔ поле ↔ план) обновляют связанные списки через `invalidateQueries`. Не изобретать глобальный EventBus.

## 7. Эталон: экран «Культуры»

Реализация: `src/features/crops/`  
Спека экрана: `docs/design.md`

Это **референс**, с которого копировать паттерны, а не экран, который каждый раз «улучшают».

### 7.1. Что уже есть и нельзя ломать без задачи

- header «Культуры организации» + «Добавить культуру»
- табы: Все / Зерновые / Масличные / Бобовые
- карточка: иконка, имя, статус, 4 параметра, sparkline прошлого сезона
- поиск `?q=`, фильтр `?category=`
- AddCropModal, CropDetailDrawer, toast, skeleton / empty / error
- модель `Crop` в `features/crops/model/types.ts`

### 7.2. Модель Crop (минимальный контракт)

Поля ниже — часть платформы. Не переименовывать, не менять union-значения.

```ts
category: 'grain' | 'oilseed' | 'legume' | 'other'
status:   'sowing_now' | 'planned' | 'history'
marginPotential: 'high' | 'medium' | 'low'
yieldUnit: 't/ha'
sowingWindow: { start: 'DD.MM'; end: 'DD.MM' }
```

Лейблы: `STATUS_LABEL`, `CATEGORY_LABEL`, `MARGIN_LABEL` в `model/labels.ts`.

### 7.3. Правила расширения культур

1. Новая информация о культуре **сначала** в Drawer, не на карточку.
2. Карточка должна считываться за 2–3 секунды.
3. Редактирование и удаление — только из Drawer, не с карточки. «Использовать в новом плане» остаётся в Drawer (пока заглушка).
4. График за 3–5 лет и список полей — секции Drawer, не отдельные страницы без нужды.
5. Связь с полем или планом не меняет вёрстку каталога, только данные.

## 7.4. Эталон: экран «Поля»

Реализация: `src/features/fields/`  
Спека: `docs/design-fields.md`

Паттерн тот же, что у культур: header + фильтры + контент + Modal/Drawer + 4 состояния.

Зафиксировано:

- header «Поля организации», подзаголовок `N полей • X га`, CTA «Добавить поле»
- фильтры: почва, предшественник, площадь + «Сбросить фильтры»; активный select зелёный
- карта сверху (~420px), таблица снизу, gap 24px
- клик по полигону или строке → правый Drawer
- создание/редактирование → Modal
- статус поля: `active` / `planned` / `in_progress` / `inactive` (Активно / Планируется / В обработке / Не активно)
- `planned` у поля — **синий**, не жёлтый (жёлтый `planned` остаётся у культур)
- таблица не больше 7 колонок; новая информация — в Drawer
- карта — главный визуальный блок, без лишних слоёв
- геометрия `GeoJSON.Polygon` хранится у поля
- контур рисуется и правится на Яндекс.Карте **в модалке** создания/редактирования
- без контура при сохранении строится служебный прямоугольник
- соседи на карте модалки показываются серым, без интерактива
- удаление — из Drawer или меню `⋯` строки, с подтверждением; поле пропадает из таблицы и с карты
- ключ стора: `cropoptimize.fields.v1`

## 7.5. Эталон: экран «Планы расчёта»

Реализация: `src/features/plans/`  
Спека: `docs/design-plans.md`

Зафиксировано:

- header «Планы расчёта» + CTA «Создать новый план»

- результаты: `/plans/:planId/results` (KPI + карта + таблица + ИИ Сводка внизу)
- на результатах стрелка «назад» слева от названия ведёт к списку планов и сохраняет фильтры списка
- ИИ Сводка: 2–4 информационные карточки из цифр результата, не кликабельные; генерация в `buildAiSummary`
- ключ стора: `cropoptimize.plans.v1`

## 8. Как добавлять новую фичу

Порядок обязательный:

1. Определить, какой **существующий** экран расширяется, или какой **placeholder** заполняется (`/settings`).
2. Повторить паттерн культур: `features/<name>/` + тонкая страница + пункт в роутере, если экран уже есть в nav.
3. Взять токены, `Button` / `Modal` / `Drawer` / `Field` / `Badge` / `Toast` из `shared/ui`.
4. Скопировать состояния loading / empty / error / filtered-empty.
5. Фильтры и поиск — в URL, не только в `useState`.
6. Не менять `AppLayout` дальше, чем нужно для поиска/сезона, если фича ими пользуется.
7. Не трогать CSS оболочку (`AppLayout.module.css`, `tokens.css`), кроме добавления **нового** токена, которого правда нет.

### 8.1. Карта экранов и как их развивать

| Route | Сейчас | Как расширять |
|---|---|---|
| `/crops` | Готовый каталог | Drawer, edit, связи. Карточку не раздувать |
| `/fields` | Готовый каталог: карта + таблица | Новые данные о поле — только в Drawer. Таблица ≤ 7 колонок |
| `/dashboard` | Статусы + активность команды | Не добавлять график длительности, KPI и ленту планов |
| `/plans` | Готовый листинг + мастер + Drawer | Не раздувать таблицу; детали в Drawer |
| `/plans/:id/results` | Результаты завершённого плана | Ровно 3 KPI; без Принять/Экспорт/Уверенность |
| `/employees` | Готовый список + приглашение | Без удаления; только статус «Неактивен» |
| `/invite/:token` | Принятие приглашения | Одноразовая ссылка, задать пароль |
| `/settings` | Placeholder | Настройки организации/профиля. Settings остаётся нижним пунктом |

Планы расчёта **используют** каталог культур и список полей, не копируют их.  
Поля **ссылаются** на культуру по имени из каталога, не хранят параллельный справочник.  
«Оптимизировать» с поля ведёт на `/plans?fieldId=`. Не рисовать второй мастер на экране полей.

### 8.2. Сезон

Селектор сезона в top bar — часть оболочки. Сезоны — сущность (`features/seasons`): список, создание, инлайн-переименование и удаление с подтверждением (кнопка рядом с селектором). Текущий id в `cropoptimize.season`. Культуры, поля и планы хранят `seasonId` и показываются только в выбранном сезоне. Второй переключатель сезона на страницах не рисовать. Нельзя удалить последний сезон.

## 9. Что считается поломкой дизайна

Считать регрессией и откатывать:

- другой primary / фон / шрифт
- сайдбар сверху, снизу или в виде иконок-only без задачи
- карточки с более чем 5 параметрами или без статусного badge
- модалки на всю ширину, кастомные «красивые» оверлеи
- новая сетка (4 колонки, masonry, карусель) на каталоге культур
- английский UI на пользовательских экранах
- зависимость от новой UI-библиотеки «чтобы быстрее»
- рефакторинг ради рефакторинга, который двигает отступы, радиусы, тени

Разрешённый рефакторинг: вынести общее в `shared/` **без** визуального дрейфа, разбить файл, заменить mock на API.
