# Design Specification: Экран «Dashboard»

**Продукт:** CropOptimize  
**Версия:** MVP 1.0  
**Дата:** 15.08.2026  
**Экран:** Dashboard  
**Ответственный дизайн:** Senior UI/UX  

Этот документ является единым источником правды (Single Source of Truth) для экрана Dashboard.  
Любая новая фича, связанная с дашбордом, должна опираться на этот файл.

---

## 1. Цель экрана

Dashboard даёт агроному и руководителю быстрый обзор состояния оптимизации в текущем сезоне:

- Сколько планов находится в каждом статусе
- Как распределена нагрузка и активность по сотрудникам
- Динамика выполнения оптимизаций во времени

**Jobs-to-be-Done:**
- «Я хочу за 5 секунд понять, сколько планов сейчас считается и сколько уже готово».
- «Я хочу видеть, кто из команды активно работает с оптимизацией».
- «Я хочу понять, растёт или падает интенсивность расчётов».

---

## 2. Позиция в навигации

**Sidebar (левое меню):**
- **Dashboard** ← активный пункт
- Планы расчёта
- Поля
- Культуры
- Settings (внизу)

Активное состояние: тёмно-зелёный фон (`#2E7D32`), белая иконка и текст.

**Иконка:** home / dashboard (lucide: `layout-dashboard` или `home`).

---

## 3. Структура экрана

```
┌─────────────────────────────────────────────────────────────────────┐
│ Top Bar (logo + search + season + notifications + user)             │
├────────────┬────────────────────────────────────────────────────────┤

│  Sidebar   │                                                        │
│            │  ┌─────────────────────┐  ┌─────────────────────────┐  │
│            │  │ Планы по статусам   │  │ Активность команды      │  │

│            │                                                        │
```

- **Максимальная ширина контента:** 1440–1600px  
- **Отступы:** 32px  
- Три основных блока, больше ничего на MVP.

---

## 4. Блоки интерфейса

### 4.1. Header
- Заголовок: **Dashboard**
- Рядом: «Сезон 2026» (можно сделать переключателем сезона в будущем)

### 4.2. Планы по статусам (Donut / Circle)

- Большой donut-chart в центре с общим количеством планов
- Сегменты:
  - `В расчёте` (зелёный)
  - `Завершён` (более светлый зелёный)
  - `Черновик` (серый)
  - `Ошибка` (красный / розовый)
- Справа от круга — легенда с количеством и процентом
- Клик по сегменту или легенде может вести на отфильтрованный список планов (будущее)

### 4.3. Активность команды

Таблица / список сотрудников:

| Элемент              | Описание                                      |
|----------------------|-----------------------------------------------|
| Аватар + Имя         | Сотрудник                                     |
| Создано              | Сколько планов создал                         |
| В работе             | Сколько сейчас в статусе «В расчёте»          |
| Завершено            | Сколько завершённых планов                    |
| Progress bar         | Визуализация доли завершённых                 |

Сортировка по умолчанию — по количеству созданных / завершённых (убывание).

### 4.4. Выполнение оптимизаций по времени

- Полноширинный line / area chart
- Ось X — время (дни или недели, переключатель «По дням / По неделям»)
- Ось Y — количество оптимизаций
- Две линии (или одна основная + пунктир):
  - **Выполнено** (solid green)
  - **Начато** (dashed / lighter green)
- Tooltip при наведении: период + значения
- Период по умолчанию: последние 30 дней

---

## 5. Состояния

### Loading
- Skeleton для donut, списка сотрудников и графика

### Empty State
- Если планов ещё нет: иллюстрация + текст «Создайте первый план оптимизации» + кнопка перехода к созданию

### Error State
- «Не удалось загрузить данные дашборда»
- Кнопка «Повторить»

```ts
interface DashboardData {
```

## 8. Accessibility

- Все графики имеют текстовые альтернативы / data-таблицы
- Контраст ≥ 4.5:1
- Интерактивные элементы имеют focus-visible
- Donut и line chart доступны с клавиатуры (по возможности)

---

## 9. Правила для будущих фич

1. На MVP Dashboard содержит **только** три блока: статусы, активность команды, график по времени.
2. Не добавлять дополнительные KPI-карточки и список последних планов без согласования.
3. Клик по статусу / сотруднику в будущем может вести на отфильтрованный список планов.
4. График должен поддерживать переключение периода (дни / недели).
5. Все данные привязаны к выбранному сезону.

---

## 10. Связанные экраны

- **Планы расчёта** — источник данных по статусам и создателям
- **Результаты расчёта** — косвенно влияют на «Завершён»
- **Поля / Культуры** — не отображаются напрямую на Dashboard в MVP
