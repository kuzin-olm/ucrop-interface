# Design Specification: Экран «Сотрудники» (Employees)

**Продукт:** CropOptimize  
**Версия:** MVP 1.0  
**Дата:** 16.08.2026  
**Экран:** Сотрудники  
**Ответственный дизайн:** Senior UI/UX  

Этот документ является единым источником правды (Single Source of Truth) для экрана «Сотрудники».  
Любая новая фича, связанная с управлением сотрудниками, должна опираться на этот файл.

---

## 1. Цель экрана

Экран «Сотрудники» позволяет администратору организации:

- Видеть список всех сотрудников
- Назначать и менять роли
- Управлять активностью (вместо удаления — статус «Неактивен»)
- Видеть дату последнего входа
- Приглашать новых сотрудников через одноразовую ссылку (без открытой регистрации)

**Jobs-to-be-Done:**
- «Я хочу добавить нового сотрудника без публичной регистрации».
- «Я хочу отключить доступ уволенному сотруднику, не удаляя его».
- «Я хочу видеть, кто и когда последний раз заходил в систему».

---

## 2. Позиция в навигации

**Sidebar (левое меню):**
- Dashboard
- Планы расчёта
- Поля
- Культуры
- **Сотрудники** ← активный пункт
- Settings (внизу)

Активное состояние: тёмно-зелёный фон (`#2E7D32`), белая иконка и текст.

**Иконка:** users / user-cog (lucide: `users`).

## 4. Элементы листинга

### 4.1. Header
- Заголовок: **«Сотрудники»**
- Справа: Primary Button `+ Пригласить сотрудника`

### 4.2. Фильтры
- Роль: Все / Администратор / Агроном / Аналитик
- Статус: Все / Активен / Неактивен

### 4.3. Таблица сотрудников

| Колонка          | Описание                                              |
|------------------|-------------------------------------------------------|
| Сотрудник        | Аватар + ФИО + Email                                  |
| Роль             | Только 3 варианта: Администратор / Агроном / Аналитик |
| Статус           | Badge: `Активен` (зелёный) / `Неактивен` (серый)      |
| Последний вход   | Дата + время или `—` / `Никогда`                      |
| Действия         | «Редактировать»                                       |

**Роли (строго 3):**
- Администратор
- Агроном
- Аналитик

**Статус:**
- `Активен` — может входить в систему
- `Неактивен` — вход запрещён (используется вместо удаления)

---

## 5. Модалка «Пригласить сотрудника»

**Триггер:** кнопка `+ Пригласить сотрудника`

**Поля:**
- ФИО * (обязательно)
- Email * (обязательно)
- Роль * (select: Администратор / Агроном / Аналитик)
- Статус (по умолчанию «Активен»)

**Ссылка-приглашение:**
- После заполнения основных полей появляется блок со ссылкой
- Кнопка «Сгенерировать ссылку» / ссылка генерируется автоматически
- Поле со ссылкой + кнопка «Копировать»
- Подпись: «Ссылка одноразовая. Сотрудник перейдёт по ней и задаст пароль.»

**Кнопки:**
- «Отмена»
- «Отправить приглашение» (или «Создать и скопировать ссылку»)

**После успешного приглашения:**
- Модалка закрывается
- Сотрудник появляется в таблице со статусом «Активен» (или ожидает принятия приглашения)
- Toast: «Приглашение создано»

---

## 6. Редактирование сотрудника

**Триггер:** кнопка «Редактировать» в строке таблицы

Открывается модалка / Drawer с полями:
- ФИО
- Email (обычно только для чтения или с осторожностью)
- Роль (Администратор / Агроном / Аналитик)
- Статус (Активен / Неактивен)

**Важно:**
- При установке статуса «Неактивен» сотрудник больше не может войти в систему.
- Удаление записи не предусмотрено в MVP.

---

## 7. Состояния

### Loading
- Skeleton-строки таблицы

### Empty State
- «Пока нет сотрудников»
- «Пригласите первого сотрудника»
- Кнопка `+ Пригласить сотрудника`

### Error State
- «Не удалось загрузить список сотрудников»
- Кнопка «Повторить»

## 8. Данные сотрудника (Data Model)

```ts
interface Employee {
  id: string;
  fullName: string;
  email: string;
  role: "admin" | "agronomist" | "analyst";
  status: "active" | "inactive";
  lastLoginAt?: string;          // ISO or null
  avatarUrl?: string;
  inviteToken?: string;          // для приглашения
  inviteExpiresAt?: string;
}
```

## 10. Accessibility

- Все интерактивные элементы имеют focus-visible
- Контраст ≥ 4.5:1
- Status Badge имеют текстовое значение
- Модалки закрываются по Escape

---

## 11. Правила для будущих фич

1. Ролей строго три: Администратор, Агроном, Аналитик.
2. Удаление сотрудников не делаем — только статус «Неактивен».
3. Регистрация только через приглашение (invite link).
4. Ссылка-приглашение должна быть одноразовой или с ограниченным сроком.
5. В будущем можно добавить историю изменений ролей и статусов.

---

## 12. Связанные экраны

- **Dashboard** — блок «Активность команды» использует данные сотрудников
- **Планы расчёта** — поле «Кто создал» берётся из сотрудников
- **Settings** — возможно общие настройки организации
