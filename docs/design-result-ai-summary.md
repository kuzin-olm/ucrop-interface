# Design Specification: Фича «ИИ Сводка» (AI Summary)

**Продукт:** CropOptimize  
**Версия:** MVP 1.0  
**Дата:** 15.08.2026  
**Фича:** ИИ Сводка на экране результатов расчёта  
**Тип:** Дополнительная (addon) к экрану Results  
**Ответственный дизайн:** Senior UI/UX  

Этот документ описывает дополнительную фичу «ИИ Сводка», которая появляется в нижней части экрана результатов оптимизации.

---

## 1. Цель фичи

После завершения расчёта система автоматически формирует 2–4 коротких вывода на основе результатов оптимизации.

Цель:
- Помочь агроному быстро понять смысл цифр
- Выделить сильные стороны плана и потенциальные риски
- Снизить когнитивную нагрузку при анализе результатов

**Jobs-to-be-Done:**
- «Я хочу сразу понять, хороший получился план или нет».
- «Я хочу увидеть, на что обратить внимание».

---

## 2. Расположение

Экран: **Результаты расчёта** (`design-plan-result.md`)

Место: **в самом низу** страницы, после блока с картой и таблицей «Рекомендации по полям».

```
┌─────────────────────────────────────────────┐
│ Header + Status                             │
│ 3 KPI-карточки                              │
│ Карта + Таблица рекомендаций                │
│                                             │
│ ┌─────────────────────────────────────────┐ │
│ │           ИИ Сводка                     │ │
│ │  [карточка] [карточка] [карточка] ...   │ │
│ └─────────────────────────────────────────┘ │
└─────────────────────────────────────────────┘
```

---

## 3. Структура блока

### 3.1. Заголовок блока
- Текст: **«ИИ Сводка»** или **«Ключевые выводы»**
- Иконка слева (sparkles / brain / lightbulb)
- Опционально: маленькая подпись «Сгенерировано на основе результатов расчёта»

### 3.2. Карточки выводов

- Количество: **от 2 до 4** карточек
- Расположение: горизонтальный ряд (на широких экранах), на узких — 2×2 сетка
- Каждая карточка:

| Элемент          | Описание                                      |
|------------------|-----------------------------------------------|
| Иконка           | Цветная (зелёная / жёлтая / красная по смыслу)|
| Заголовок        | 3–6 слов, bold                                |
| Описание         | 1–2 коротких предложения                      |

**Пример структуры карточки:**
```
[иконка] Высокий потенциал доходности
         План обеспечивает рост маржи
         на 18% по сравнению со средними
         показателями за 5 лет.
```

---

## 4. Типы выводов (рекомендуемые)

Система может генерировать выводы следующих категорий:

1. **Доходность / Маржа**  
   Пример: «Высокий потенциал доходности»

2. **Баланс культур / Севооборот**  
   Пример: «Оптимальное чередование культур»

3. **Риски**  
   Пример: «Рекомендации по рискам» (конкретные поля)

4. **Распределение площади**  
   Пример: «Концентрация площади» или «Хорошее распределение»

5. **Уверенность / Качество данных** (опционально)  
   Пример: «Высокая уверенность модели»

В одном блоке не должно быть двух одинаковых по смыслу карточек.

---

## 5. Поведение

- Блок появляется **только** на экране результатов завершённого плана.
- Если данных недостаточно для генерации — блок скрывается или показывает 2 самых общих вывода.
- Карточки в MVP **не кликабельные** (чисто информационные).
- Загрузка: можно показать skeleton из 3 карточек, пока ИИ-сводка генерируется.

---

## 6. Данные (Data Model)

```ts
interface AiSummaryCard {
  id: string;
  type: "margin" | "rotation" | "risk" | "distribution" | "confidence";
  icon: string;               // ключ иконки
  title: string;              // "Высокий потенциал доходности"
  description: string;        // 1–2 предложения
  severity?: "positive" | "warning" | "neutral";
}

interface AiSummary {
  planId: string;
  cards: AiSummaryCard[];     // 2–4 элемента
  generatedAt: string;
}
```

---

## 7. Визуальные правила

- Карточки в стиле остальных surface-элементов:
  - Background: `#FFFFFF`
  - Border-radius: `16px`
  - Мягкая тень
  - Padding: 16–20px
- Иконки — зелёные (positive), жёлтые/оранжевые (warning)
- Заголовок блока — 18–20px SemiBold
- Текст описания — 14px, `#5C6B5C`

Токены берутся из общей дизайн-системы CropOptimize.

---

## 8. Accessibility

- Каждая карточка должна иметь понятный текстовый контент (не только иконка)
- Контраст текста ≥ 4.5:1
- При генерации показывать loading-состояние

---

## 9. Правила для будущих фич

1. Не делать карточки кликабельными в первой версии.
2. Не показывать больше 4 карточек.
3. Текст должен быть конкретным и опираться на реальные цифры результатов.
4. При изменении алгоритма генерации — обновлять только backend/AI-часть, визуал остаётся прежним.
5. Блок является **дополнительной фичей** и не должен ломать основной layout результатов.
