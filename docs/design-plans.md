# Design Specification: Экран «Планы расчёта» (Calculation Plans)

**Продукт:** CropOptimize  
**Версия:** MVP 1.0  
**Дата:** 15.08.2026  
**Экран:** Планы расчёта  
**Ответственный дизайн:** Senior UI/UX  

Этот документ является единым источником правды (Single Source of Truth) для экрана «Планы расчёта».  
Любая новая фича, связанная с планами оптимизации, должна опираться на этот файл.  
Документ построен по той же структуре и принципам, что и design.md для «Культуры» и «Поля».

---

## 1. Цель экрана

Экран «Планы расчёта» позволяет агроному и администратору организации:

- Видеть все созданные планы оптимизации в табличном виде.
- Отслеживать статус процесса расчёта в реальном времени.
- Открывать детальную информацию о плане в правом Drawer.
- Создавать новые планы через пошаговый мастер.
- Управлять планом: запускать, останавливать, редактировать, удалять.

**Jobs-to-be-Done:**
- «Я хочу видеть все свои планы и их текущий статус».
- «Я хочу понимать, кто и когда создал план, и сколько длился расчёт».
- «Я хочу открыть план и увидеть параметры + лог выполнения».
- «Я хочу создать новый план оптимизации за несколько шагов».

---

## 2. Позиция в навигации

**Sidebar (левое меню):**
- Dashboard
- **Планы расчёта** ← активный пункт
- Поля
- Культуры
- Settings (внизу)

Активное состояние: тёмно-зелёный фон (`#2E7D32`), белая иконка и текст.

**Иконка в сайдбаре:** документ / калькулятор (lucide: `file-text` или `calculator`).

---

## 3. Структура экрана (Listing)

```
┌─────────────────────────────────────────────────────────────────────┐
│ Top Bar (logo + search + season + notifications + user)             │
├────────────┬────────────────────────────────────────────────────────┤
│            │  Header: «Планы расчёта»  +  [+ Создать новый план]    │
│  Sidebar   │                                                        │
│            │  Filters: Статус | Кто создал | Период                 │
│            │                                                        │
│            │  ┌─────────────────────────────────────────────────┐   │
│            │  │                  Таблица планов                  │   │
│            │  │  Название | Статус | Кто создал | Когда |       │   │
│            │  │  Длительность | Действия                        │   │
│            │  └─────────────────────────────────────────────────┘   │
│            │                                                        │
│            │  (Empty / Loading / Error — при необходимости)         │
└────────────┴────────────────────────────────────────────────────────┘
```

- **Максимальная ширина контента:** 1440–1600px  
- **Отступы контента:** 32px  
- **Таблица** — основной элемент экрана

---

## 4. Элементы листинга

### 4.1. Header
- Заголовок: **«Планы расчёта»** (24–28px, SemiBold)
- Справа: Primary Button `+ Создать новый план`

### 4.2. Фильтры
- Статус процесса
- Кто создал
- Период создания
- Поиск по названию

### 4.3. Таблица планов

| Колонка            | Описание                                                                 |
|--------------------|--------------------------------------------------------------------------|
| Название           | Иконка + Название (bold) + короткое описание под ним                     |
| Статус процесса    | Badge: `В расчёте` / `Завершён` / `Черновик` / `Ошибка`                  |
| Кто создал         | Аватар + Имя + роль (Агроном / Аналитик и т.д.)                          |
| Когда создал       | Дата + время (ДД месяц ГГГГ, ЧЧ:ММ)                                      |
| Длительность       | `12 мин 34 сек` — только если процесс завершён, иначе `—`                |
| Действия           | Кнопка «Открыть» (открывает правый Drawer)                               |

**Статус Badge:**
- `В расчёте` → зелёный (`#E8F5E9` + `#2E7D32`) + точка
- `Завершён` → зелёный успех
- `Черновик` → серый
- `Ошибка` → красный / розовый

**Визуальные токены таблицы:**
- Background строк: `#FFFFFF`
- Hover: `#F1F8F1`
- Border: `#E0E7E0`
- Radius обёртки: `16px`
- Padding ячеек: `14–18px`

---

## 5. Правый Drawer — Детали плана

При клике «Открыть» (или по строке) открывается **правый Drawer** шириной **420–480px**.

### Структура Drawer

1. **Шапка**
   - Название плана
   - Status Badge
   - Кнопка закрытия (X)

2. **Параметры**
   - Цель плана
   - Выбранные поля (количество + общая площадь)
   - Культуры (chips)
   - Ограничения:
     - Лимит бюджета
     - Процент отклонения маржинальной доходности между годами
     - Площадь на культуру (мин / макс)

3. **Лог процесса**
   - Простой хронологический список
   - Каждая запись: `ЧЧ:ММ:СС — текст сообщения`
   - Логи прилетают постепенно по ходу выполнения процесса
   - Нет фиксированных этапов — просто отображаем входящие сообщения
   - Последняя запись может иметь иконку успеха / ошибки

4. **Действия (внизу Drawer, sticky)**
   - `Запустить` (primary green) — если план в статусе Черновик или Ошибка
   - `Остановить` (outline) — если план в статусе «В расчёте»
   - `Редактировать` (ghost / secondary)
   - `Удалить` (danger / red)

**Поведение Drawer:**
- Наезжает справа поверх контента
- Overlay затемняет основной экран
- Закрытие: X, клик по overlay, Escape
- Анимация: slide-in справа

---

## 6. Флоу создания нового плана (Wizard)

**Триггер:** кнопка `+ Создать новый план`

**4 шага + возможность вернуться и изменить данные.**

### Шаг 1. Название, описание и цель
- Название плана * (обязательно)
- Описание (необязательно)
- Цель плана (radio-cards):
  - **Максимизация маржинальной прибыли** — активная
  - Три остальные цели — disabled (с меткой «Скоро»)

### Шаг 2. Выбор полей
- Интерактивная карта + список полей с чекбоксами
- Счётчик: «Выбрано: X полей • Y га»
- Поиск и фильтры

### Шаг 3. Выбор культур + ограничения
- Мультивыбор культур (chips)
- Ограничения в виде карточек:
  1. Лимит бюджета (₽)
  2. Процент отклонения маржинальной доходности между годами (%)
  3. Площадь на культуру (Минимум / Максимум га)

### Шаг 4. Подтверждение
- Сводка всех выбранных данных
- Кнопки «Изменить» напротив каждого блока (возвращают на соответствующий шаг)
- Primary кнопка «Запустить расчёт»
- После запуска: план появляется в таблице со статусом «В расчёте»

На каждом шаге: «Назад» / «Далее».  
На шаге 4 можно кликнуть по любому предыдущему шагу в прогресс-баре.

## 7. Состояния экрана

### Loading
- Skeleton-строки таблицы

### Empty State
- Заголовок: «Пока нет планов расчёта»
- Подзаголовок: «Создайте первый план оптимизации»
- Primary Button: `+ Создать новый план`

### Error State
- «Не удалось загрузить планы»
- Кнопка «Повторить»

### Нет результатов фильтрации
- «По выбранным фильтрам ничего не найдено»
- «Сбросить фильтры»

## 8. Данные плана (Data Model)

```ts
interface CalculationPlan {
  id: string;
  name: string;
  description?: string;
  goal: "maximize_margin";          // пока только одна цель
  status: "draft" | "calculating" | "completed" | "error";
  createdBy: {
    id: string;
    name: string;
    role: string;
    avatarUrl?: string;
  };
  createdAt: string;                // ISO
  durationSeconds?: number;         // только если completed
  fieldsCount: number;
  totalArea: number;
  crops: string[];
  constraints: {
    budgetLimit?: number;
    marginDeviationPercent?: number;
    minAreaPerCrop?: number;
    maxAreaPerCrop?: number;
  };
  logs: {
    timestamp: string;
    message: string;
  }[];
}
```

## 10. Accessibility

- Все интерактивные элементы имеют `focus-visible` кольцо зелёного цвета
- Контраст ≥ 4.5:1
- Таблица и Drawer доступны с клавиатуры
- Status Badge имеют текстовое значение
- Drawer закрывается по Escape

---

## 11. Правила для будущих фич

1. Таблица — главный элемент листинга. Не превращать в карточки без необходимости.
2. Лог в Drawer — простой список сообщений, без фиксированных этапов.
3. Статус процесса — самый важный визуальный маркер.
4. Действия «Запустить / Остановить» зависят от текущего статуса.
5. При создании плана должна быть возможность выбрать несколько полей.
6. Паттерн правого Drawer’а должен оставаться идентичным Drawer’ам Полей и Культур.
