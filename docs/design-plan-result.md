# Design Specification: Экран «Результаты расчёта» (Plan Results)

**Продукт:** CropOptimize  
**Версия:** MVP 1.0  
**Дата:** 15.08.2026  
**Экран:** Результаты расчёта плана  
**Ответственный дизайн:** Senior UI/UX  

Этот документ является единым источником правды (Single Source of Truth) для экрана результатов оптимизации.  
Любая новая фича, связанная с отображением результатов плана, должна опираться на этот файл.

---

## 1. Цель экрана

Экран «Результаты расчёта» показывает итог выполненной оптимизации:

- Ключевые показатели плана (маржа, площадь, количество полей)
- Визуальное распределение рекомендованных культур по полям (карта)
- Детальные рекомендации по каждому полю (урожайность + маржа)

**Jobs-to-be-Done:**
- «Я хочу сразу увидеть, какая маржа получилась».
- «Я хочу понять, какую культуру на какое поле рекомендует система».
- «Я хочу быстро сравнить прогноз урожайности и маржи по полям».

---

## 2. Позиция в навигации и вход

**Как попасть на экран:**
- Из таблицы «Планы расчёта» → клик «Открыть» у завершённого плана → в Drawer нажать на результаты / или прямой переход
- Из Drawer плана (когда статус = «Завершён») — ссылка/кнопка «Смотреть результаты»

**Sidebar:**
- Dashboard
- **Планы расчёта** (активный или подсвеченный)
- Поля
- Культуры
- Settings

## 4. Элементы интерфейса

### 4.1. Header
- Название плана (крупно)
- Status Badge: `Завершён` (зелёный)
- Подзаголовок (опционально): «План расчёта завершён • Результаты оптимизации»
- **Нет кнопок действий** в header (Принять план / Экспорт / Дублировать — отсутствуют)

### 4.2. KPI-карточки (только 3)

| Карточка              | Значение                  | Подпись              |
|-----------------------|---------------------------|----------------------|
| Прогнозная маржа      | `+28 450 ₽/га`            | на 1 га              |
| Общая площадь         | `1 240 га`                | по X полям           |
| Полей в плане         | `8`                       | в обработке          |

- Карточка «Средняя урожайность» — **не используется**.

### 4.3. Карта полей
- Показывает полигоны полей, раскрашенные по рекомендованной культуре
- Легенда культур (цвет + название + суммарная площадь)
- Контролы zoom
- Подписи на полигонах: название поля + площадь

### 4.4. Таблица «Рекомендации по полям»

**Колонки (строго):**

| Колонка                     | Описание                          |
|-----------------------------|-----------------------------------|
| Поле                        | Цветная метка + Название поля     |
| Рекомендованная культура    | Название + иконка культуры        |
| Прогноз урожайности (т/га)  | Число                             |
| Прогноз маржи (₽/га)        | Число со знаком `+`               |

**Убрано:**
- Колонка «Уверенность»
- Колонка «Действия» / «Подробнее»

Таблица может иметь лёгкую пагинацию или «Показать все», если полей много.

## 5. Состояния

### Loading
- Skeleton KPI + skeleton карты + skeleton таблицы

### Empty / Нет данных
- Не должно происходить для завершённого плана (результаты всегда есть)

### Error
- «Не удалось загрузить результаты»
- Кнопка «Повторить»

## 6. Данные результатов (Data Model)

```ts
interface PlanResult {
  planId: string;
  planName: string;
  status: "completed";
  kpis: {
    predictedMarginPerHa: number;   // ₽/га
    totalArea: number;              // га
    fieldsCount: number;
  };
  fieldRecommendations: {
    fieldId: string;
    fieldName: string;
    recommendedCrop: string;
    predictedYield: number;         // т/га
    predictedMarginPerHa: number;   // ₽/га
    color?: string;                 // для карты
  }[];
  mapGeometry: GeoJSON;             // полигоны полей
}
```

## 8. Accessibility

- Контраст ≥ 4.5:1
- Карта имеет текстовые альтернативы (легенда + таблица)
- Таблица полностью доступна с клавиатуры
- Status Badge имеет текстовое значение

---

## 9. Правила для будущих фич

1. Не добавлять кнопки «Принять / Экспорт / Дублировать» в header без отдельного согласования.
2. Не возвращать колонки «Уверенность» и «Действия» в таблицу рекомендаций.
3. KPI-карточек должно оставаться ровно три (маржа, площадь, количество полей).
4. Карта и таблица должны показывать согласованные данные.
5. При клике на полигон карты можно в будущем открывать мини-информацию о поле (не в MVP).
